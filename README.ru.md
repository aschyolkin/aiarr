# Media Acquisition Engine (aiarr)

[English](README.md) · **Русский**

Self-hosted замена Radarr и Sonarr, рассчитанная на русскоязычные торрент-трекеры.
Пользователи делают заявки в [Seerr](https://github.com/seerr-team/seerr); aiarr находит
релиз, скачивает его через qBittorrent, проверяет настоящий файл через ffprobe,
публикует в библиотеку жёсткой ссылкой и ждёт, пока его увидит Jellyfin.

> **При выборе релиза используется ИИ.** Допустимость и оценку кандидатов определяют
> фиксированные правила. Если карточка релиза неоднозначна (например, неясны язык аудио
> или кодек), её читает языковая модель ([DeepSeek](docs/DEEPSEEK.md)); она может вернуть
> только утверждения с цитатой из карточки, а скачанный файл всё равно проверяется ffprobe.
> Шаг необязателен, ограничен бюджетом, а без API-ключа неясные релизы просто ждут ручной
> проверки.

```
Заявка в Seerr ─► поиск по источникам ─► выбор релиза ─► qBittorrent
                                                             │
Jellyfin ◄─ импорт жёсткой ссылкой ◄─ проверка ffprobe ◄─────┘
```

Работает в Docker на любой Linux-машине и в production на домашнем сервере заменил Radarr
и Sonarr.

## Возможности

**Поиск релизов**
- Источники: любой Torznab-индексатор (Prowlarr, Jackett), встроенные анонимные адаптеры
  NNM-Club и Rutor и документированный JSON-протокол для собственных источников
  ([Adapter SDK](docs/ADAPTER_SDK.md)).
- Источники опрашиваются параллельно. Один и тот же торрент из нескольких источников
  (по infohash) считается одним кандидатом. Карточки релизов кэшируются.
- Torznab-индексаторы, объявляющие поддержку `tmdbid`/`tvdbid`, дополнительно ищутся по
  ID; источник можно ограничить категориями Torznab.
- Поиск идёт по названию, по латинскому псевдониму (чтобы находились раздачи
  «Рус / Eng») и по английскому названию иноязычных работ.
- Ручной поиск по произвольному тексту на странице заявки с загрузкой любого результата
  одной кнопкой.

**Выбор релиза**
- Допустимость решают детерминированные правила: название и год, сезон и серии,
  разрешение (предпочтительно 2160p/1080p, запасной вариант 720p), видеокодек, качество
  источника (CAM/телесинк отбрасываются), лимиты размера и обязательная русская дорожка.
- Оценка предпочитает лучший источник, разрешение, H.265, дубляж перед многоголосой и
  одноголосой озвучкой и настраиваемые веса студий (LostFilm, NewStudio и др.).
- Разбираются заголовки и карточки русских трекеров
  (`Рус / Eng (2024) [WEB-DL 1080p] | D, P2`).
- Необязательный DeepSeek с лимитами на токены трактует неясные карточки. Каждое
  утверждение обязано цитировать источник, а файл всё равно проверяется ffprobe.
- Если ни один релиз не подтверждён полностью (например, в карточке не указан язык
  дорожки), решает ИИ: качать лучший из них или нет. Причина решения записана в «Ходе
  заказа» на двух языках. Без ключа DeepSeek берётся лучший по баллам. Загруженный файл
  проверяет ffprobe, неподходящий отбрасывается и берётся следующий релиз; когда
  подходящих не остаётся, заявка ждёт новых раздач, а не «Требуется проверка».
  Отключается настройкой «Качать лучший релиз, даже если часть данных не подтверждена».
  Выбранный вручную релиз при ошибке проверки остаётся на ручной разбор.

**Загрузка**
- Второй по рейтингу релиз стартует на низкой скорости рядом с основным. Мёртвая или
  слишком медленная раздача заменяется за минуты; медленная остаётся только как
  последний вариант.
- Место на диске резервируется заранее. Доступны лимит очереди, расписание скорости
  (альтернативные лимиты в заданные часы) и чистка отданных торрентов (по возрасту или
  по рейтингу раздачи).
- Сериалы: внутри пака выбираются только недостающие серии. Серии, которые ещё не вышли,
  не ищутся; заявка ждёт даты выхода следующей.

**Проверка и импорт**
- Каждый видеофайл проверяется ffprobe: кодек, разрешение, русская дорожка. Файл, не
  прошедший проверку, отклоняется, торрент удаляется, и автоматически пробуется
  следующий релиз.
- Импорт — журналируемая жёсткая ссылка с проверкой device и inode: сбой не оставит
  наполовину опубликованный файл. Имена по схеме Jellyfin (`Название (Год) [tmdbid-N]`).
- Релизы получше ищутся позже (фильмы и сериалы) и либо предлагаются, либо заменяют файл
  автоматически. Старый файл отодвигается и возвращается, если новый не прошёл проверку.

**Эксплуатация**
- Веб-интерфейс `/admin`: карточки заявок с прогрессом, таблица кандидатов с причиной
  каждого решения, лента событий, здоровье источников, календарь серий и все настройки.
  Вход через открытую админскую сессию Seerr или по API-ключу. Язык интерфейса
  (русский/английский) переключается кнопкой EN/RU в меню.
- Сериал, для которого в TMDB нет TVDB-id, находится по названию в окне Seerr «сопоставьте
  сериал» и дальше ведётся по TMDB-id.
- Фасад, совместимый с Seerr (`/radarr/api/v3`, `/sonarr/api/v3`): Seerr общается с aiarr
  как с Radarr и Sonarr.
- Удаление заявки в Seerr удаляет файлы и торрент, принадлежащие aiarr, после проверки
  категории, тега, пути, inode и device. Больше ничего не удаляется.
- По умолчанию включён dry-run: ничего не скачивается и не пишется в библиотеку.

## Архитектура

| Часть | Назначение |
|---|---|
| `mae/api.py`, `mae/admin.py` | Сервис FastAPI: админка и API, фасад Radarr/Sonarr |
| `mae/worker.py` | Один долгоживущий worker: поиск, контроль загрузок, импорт, апгрейды, чистка |
| `mae/db.py`, `migrations/` | Журнал заданий в SQLite (WAL) и миграции Alembic |
| `mae/providers.py`, `mae/enrichment.py` | Адаптеры источников и разбор карточек релизов |
| `mae/parsing.py`, `mae/policies.py` | Извлечение признаков, правила допустимости и оценка |
| `mae/downloads.py` | Клиент qBittorrent с проверкой владельца в каждой операции |
| `mae/verification.py`, `mae/importing.py` | Проверки ffprobe, публикация жёсткой ссылкой, пути библиотеки |
| `mae/seerr.py`, `mae/jellyfin.py` | Сверка с Seerr и проверка библиотеки Jellyfin |
| `mae/deepseek.py` | Необязательная трактовка LLM с бюджетами и кэшем |

Из одного образа запускаются два процесса, `api` и `worker`, и одноразовый `migrate`.
Файловая блокировка гарантирует единственный worker. Состояние лежит в одном каталоге
(`MAE_STATE_DIR`): база, настройки из интерфейса и блокировка.

Принятые решения: [ADR-001](docs/ADR-001-core.md), [контракт Seerr](docs/SEERR_CONTRACT.md),
[матрица источников](docs/SOURCE_SUPPORT_MATRIX.md), [протокол приёмки](docs/ACCEPTANCE.md).

## Требования

- Seerr, qBittorrent (с включённым Web UI), Jellyfin и хотя бы один источник поиска.
- Одна файловая система с каталогом загрузок и библиотекой — импорт делается жёсткой
  ссылкой. Путь к ней — `MAE_STORE_HOST` на хосте и `/data/store` в контейнерах:
  ```
  /data/store/downloads/{films,serials}   сюда сохраняет qBittorrent
  /data/store/films                       библиотека фильмов
  /data/store/serials                     библиотека сериалов
  ```
- Linux с Docker и плагином Compose (в образе есть ffmpeg) либо Python 3.12 с `uv` и
  `ffprobe` для запуска без Docker.

## Установка

### Скрипт установки

```sh
curl -fsSL https://raw.githubusercontent.com/aschyolkin/aiarr/main/install.sh | bash
```

или из клона репозитория: `./install.sh`. Скрипт:

1. проверяет Docker, плагин Compose и доступность демона;
2. скачивает aiarr (если запущен не из клона) и спрашивает каталог с медиа, адреса и ключи
   qBittorrent, Jellyfin и Seerr, а также необязательный ключ DeepSeek;
3. пишет `.env` (права 600) со сгенерированным API-ключом, безопасно экранируя значения;
4. создаёт недостающие каталоги медиа и каталог состояния с нужным владельцем
   (существующие каталоги и файлы не трогает);
5. собирает образ, из контейнера проверяет, что каталоги доступны для записи, а
   qBittorrent, Jellyfin и Seerr достижимы, и запускает всё;
6. ждёт готовности API и выводит дальнейшие шаги.

Повторный запуск безопасен: существующий `.env` сохраняется (`AIARR_RECONFIGURE=1`
спросит заново и оставит копию), а образ пересобирается и перезапускается — так же
проходит обновление (`git pull && ./install.sh`). Для запуска без вопросов задайте
переменные `MAE_*` из `.env.example` и `AIARR_YES=1`. Реальные загрузки остаются
выключенными (`MAE_DRY_RUN=true`), пока вы не ответите «да» на вопрос.

Сервисы на этой же машине доступны из контейнера как `http://host.docker.internal:<порт>`;
`127.0.0.1` внутри контейнера — это сам контейнер.

### Ручная установка

```sh
cp .env.example .env && chmod 600 .env
# задайте MAE_API_KEY (24+ случайных символа), MAE_STORE_HOST, MAE_STATE_HOST и адреса и
# ключи qBittorrent, Jellyfin и Seerr
mkdir -p "$STATE" && sudo chown 3000:3000 "$STATE"   # каталог состояния ($MAE_STATE_HOST)
docker compose up -d --build                         # миграции, затем api и worker
```

### После установки

API слушает `MAE_BIND:MAE_PORT` (по умолчанию `127.0.0.1:30280`; скрипт предлагает
`0.0.0.0`, чтобы Seerr из другого контейнера мог до него достучаться, поэтому в
недоверенной сети поставьте перед ним файрвол или обратный прокси). Любой запрос
требует аутентификации.

1. Откройте `http://<хост>:30280/admin`, войдите в Seerr администратором в том же
   браузере и добавьте источники на странице «Источники».
2. В Seerr добавьте серверы Radarr и Sonarr с адресами `http://<хост>:30280/radarr` и
   `http://<хост>:30280/sonarr`, ключом `MAE_API_KEY` и профилем качества `1`.
3. По умолчанию `MAE_DRY_RUN=true`: сделайте заявку, убедитесь, что выбирается правильный
   релиз, затем поставьте `MAE_DRY_RUN=false` в `.env` и выполните `docker compose up -d`.

Заметки об обновлении и откате: [Deployment](docs/DEPLOYMENT.md).

## Настройка

Переменные окружения (префикс `MAE_`, см. `.env.example`) задают начальные значения.
Большинство параметров затем правится в админке и сохраняется в `runtime-config.json` в
каталоге состояния; worker применяет изменения в течение десяти секунд. Секреты в браузер
не возвращаются: пустое поле секрета оставляет прежнее значение.

| Область | Параметры |
|---|---|
| Качество | разрешения, запасные разрешения, кодеки, лимиты размера, веса и запрещённые источники видео, обязательность русской дорожки, веса озвучки и студий |
| Загрузки | число параллельных загрузок, время простоя, минимум сидов и скорости, предельная длительность, резерв диска, расписание скорости |
| Апгрейды и чистка | интервал поиска лучшего релиза, автозамена, чистка по возрасту или рейтингу, кэш карточек |
| Источники | для каждого: протокол, URL, ключ, Cookie, интервал запросов, селектор карточки, категории |
| DeepSeek | ключ и дневные/на-запрос лимиты (необязательно) |

Настройка источников, подключение шлюза Prowlarr и список проверенных трекеров —
в [матрице источников](docs/SOURCE_SUPPORT_MATRIX.md). Секреты (ключи, Cookie, адреса
с passkey) не попадают в логи, сообщения об ошибках и сохранённые доказательства.

## Командная строка

```sh
mae migrate     # применить миграции базы
mae api         # админка и API на :8080
mae worker      # цикл worker
mae once        # один проход worker
mae reconcile   # один раз сверить заявки с Seerr
python -m mae.backup backup <каталог-состояния> <каталог-снимка>   # согласованный снимок SQLite
```

## Разработка

```sh
uv sync --frozen
uv run pytest -q                 # офлайн-тесты, для тестов импорта нужен ffmpeg
uv run ruff check mae migrations tests
```

`tests/live_*.py` — необязательные скрипты для настоящих Seerr, Jellyfin, qBittorrent и
DeepSeek; `pytest` их не собирает. Не коммитьте `.env`, Cookie, passkey и данные
аккаунтов.
